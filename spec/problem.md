# 1. Problem

## 1.1. Задача

Имена хостов должны указывать на текущий рабочий адрес, даже когда адрес
меняется. IPv6-префикс у домашнего провайдера меняется при перезагрузке
роутера; у части хостов публичного IPv4 нет вовсе — они стоят за NAT.

Нужен способ, которым хост сам сообщает свои адреса, не требуя открытого API,
токенов и правок у регистратора.

## 1.2. Ограничения

| Ограничение | Следствие |
| --- | --- |
| NSD не поддерживает RFC 2136 | зоны нельзя править на месте; только перегенерировать файлы |
| Хосты бывают за NAT, без публичного адреса | работаем по схеме «хост идёт сам», а не «сервер спрашивает хост» |
| Публичный IPv4 за NAT не виден хосту | адрес берём из `SSH_CONNECTION` на NS-хосте |
| У хостов уже есть SSH-ключ | аутентификация без нового секрета |
| Зона делегирована вручную у регистратора | подзоны создаём сами, родительская зона не наша |
| Обрыв связи до 10 минут | данные не теряются: хост повторит на следующем тике |
| Фильтрация трафика по семействам | политика публикации задаётся явно (ADR-0005) |
| NS должен работать на дешёвом VPS | лёгкий NSD, без БД (ADR-0009) |
| зоны не правятся в UI провайдера | состояние/зоны из конфига (ADR-0010) |

## 1.3. Критерий приёмки

После перезагрузки хоста и NS-хоста имя разрешается в актуальный адрес без
ручных действий, а набор опубликованных семейств соответствует политике.

## 1.4. Эксплуатация существующего NS

NS не обязан быть чистым: на нём уже может работать NSD с
`/etc/nsd/nsd.conf`, где заданы `ip-address`, `zonesdir` и старые зоны
(старый конфиг зон). Обновление не должно оставлять зону без DNS.

Требования:

- `bootstrap-nsd` не перезапускает работающий NSD вслепую: сравнивает
  конфиг, сохраняет старый, находит старый unit/процесс (в том числе в
  другом network namespace), останавливает его и запускает управляемый;
  при неудаче возвращает старый конфиг (ADR-0007);
- `ip-address`, уже заданный в main-конфиге, не дублируется: иначе NSD
  биндит адрес дважды и падает с `EADDRINUSE`, а `ss` пуст (ADR-0008);
- `systemd-resolved` на 127.0.0.53/54 не отключается: NSD слушает конкретные
  адреса хоста и loopback (ADR-0006);
- владельца 53 можно увидеть через `make nsd-who HOST=<ns>`, в том числе в
  контейнере/netns;
- старые зоны/конфиги не дублируют новые: один конфиг на проект;
- `make status` показывает, что реально отдаёт NS, и завершается успехом
  только когда имена соответствуют политике.

Критерий: после обновления существующего NS `make status` печатает
`ИТОГ: всё на месте и соответствует политике`, а `dig` отдаёт записи,
требуемые политикой: `ipv6` — только AAAA, `nat,ipv6` — AAAA и A,
`ipv4,ipv6` — оба.
