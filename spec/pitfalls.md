# 6. Грабли

Каждая строка — реальная потеря времени. Симптом почти никогда не указывает на
причину, поэтому таблица ведётся по принципу «что видели → почему».

## 6.1. NSD и зоны

| Симптом | Причина | Решение |
| --- | --- | --- |
| зона «добавлена» (ok), но dig отвечает REFUSED | nsd-control addzone <файл> — второй аргумент это **pattern**, а не путь | зоны только через конфиг |
| could not open zone list /var/lib/nsd/zone.list: Permission denied | файл создан root, служба читает под nsd | zonelistfile в /run/nsd |
| `nsd-checkconf: at '\tdo-ip4:' syntax error` | в heredoc без кавычек `\t` — два символа, а не табуляция | печатать конфиг через `printf`, проверять `cat -A` |
| `nsd-checkconf: at 'listen:' syntax error` | `listen` — директива BIND/Knot | у NSD `ip-address:` (или `interface:`) |
| `can't bind 0.0.0.0@53: Address already in use` | на Ubuntu/Debian порт держит `systemd-resolved` (127.0.0.53:53) | отключить резолвер на выделенном DNS или освободить порт |
| зоны создались с чужим доменом | BASE не доходит до forced command; остаётся дефолт | BASE в `/etc/<NAME>/base`, читать в `zonegen` |
| имя осталось в старой зоне | приёмник заменял файл только в зонах нового payload | сверять весь объявленный набор зон |
| пустая зона висит в конфиге | удалялись файлы, но не каталоги | не обслуживать пустые каталоги и удалять их |
| зона не загружается после публикации | адрес не проверялся как IP | строгая проверка IPv4/IPv6 и служебных диапазонов |
| AAAA отвергается на NS с выключенным IPv6 | проверка через `getent ahosts` зависит от стека ядра | разбирать IPv6 синтаксически, без `getent` |
| «ok», но NSD не перечитал данные | ошибки `nsd-control`/`systemctl` глушились `|| true` | возвращать ошибку, если NSD не активен |
| zonegen: Permission denied в ExecStartPre | в старых пакетах песочница nsd запрещала запись | генерация отдельным юнитом `Before=nsd`; в актуальных пакетах есть `ReadWritePaths`, но полагаться на это не хотим |
| start request repeated too quickly | systemd блокирует юнит после пяти падений | systemctl reset-failed nsd |
| новые имена не видны, помогает только restart nsd | nsd-control reconfig перечитывает **конфиг**, а не данные зон | добавить nsd-control reload |
| дубль зоны в двух конфигах | остался конфиг прежнего проекта | один файл конфигурации на проект |

## 6.2. Установка и права

| Симптом | Причина | Решение |
| --- | --- | --- |
| `apt-get update`: EXPKEYSIG/404 в чужом репозитории | сторонний репозиторий сломан, update возвращает 100 | скрипт продолжает установку `nsd`; чужой репозиторий чинят или отключают отдельно |
| установщик рапортует успех, а на хосте нет скрипта | `bootstrap-host` молча пропускал отсутствующий файл | проверять комплект до root-действий |
| ключ хоста не принят на NS | `install-sender` создавал ключ, но публичную половину никто не клал в `authorized_keys` | `authorize.sh` + forced command приёмника |
| сервис публикации работает от root | `install-sender` брал `id -un` вместо переданного `RUN_USER` | `RUN_USER="${RUN_USER:-$(id -un)}"` |
| sudo: a terminal is required | sudo без NOPASSWD в неинтерактивной сессии | NOPASSWD на один установщик, вызов через sudo -n |
| sudo -n test просит пароль | команда не входит в список разрешённых | выполнять проверку внутри установщика, который уже под sudo |
| вывод установки превращается в мусор (== 59:) | ssh -t оставляет локальный терминал в raw-режиме | не держать pty во время работы: пароль отдельно, установка без pty |
| sudo: a password is required после sudo -v в другой сессии | timestamp_type=tty: подтверждение привязано к терминалу | не разделять ввод пароля и работу между сессиями |
| приёмник: command not found | в authorized_keys остался старый путь forced command | править command="…" при переименовании |
| sudo: /usr/local/bin/…: command not found | путь в sudoers не совпал с новым именем скрипта | пересоздавать правило вместе со скриптом |
| $NAME в путях на хосте | подстановка внутри **одинарных** кавычек не раскрывается | подставлять только в двойных, проверять grep после установки |

## 6.3. Скрипты и данные

| Симптом | Причина | Решение |
| --- | --- | --- |
| Is a directory при записи зоны | mkdir на пути, который потом используется как файл | каталог и файл не должны совпадать |
| read съедает строку реестра целиком | IFS= отключает разбиение по пробелам | не задавать IFS без необходимости |
| цикл обрабатывает только первый хост | ssh внутри while read читает stdin | ssh -n |
| скрипт молча завершается успехом | выход при отсутствии файла и при отсутствии доступа не различались | «нет файла» → 0, «нет доступа» → ошибка |
| ssh -t висит при перехвате вывода | псевдотерминал внутри $( ) | без -t там, где нужен вывод |
| /var/lib/<NAME>/last: Permission denied | каталог создан установщиком приёмника (root), а сервис работает под пользователем | `install-sender` заранее создаёт `last` и отдаёт файл пользователю |
| приватный IPv4 попадает в зону | отправитель не фильтровал RFC1918 | фильтр в отправителе и проверка в приёмнике |
| temporary IPv6 сменился через 15 минут | брали первый global-адрес, а он temporary | пропускать temporary/deprecated/ULA до выбора |
| nat-хост остался без имён | имена без адресов отбрасывались до подклейки nat | хранить объявленные имена отдельно |
| после смены NS данные не пришли | NS не входил в ключ состояния отправителя | включить NS в ключ и поднять версию схемы |
| после prune и повторного добавления имён нет | локальный `last` совпадает, отправитель не шлёт | установщик очищает `last`, публикация повторяется |
| установленный отправитель: «NS не задан» | `sed` заменил `@NS@` везде, включая проверку шаблона | собирать шаблон из частей; тест на установленную копию |
| опубликован IPv6 до завершения DAD | адрес ещё `tentative` | фильтровать `tentative`/`dadfailed` вместе с temporary |
| имя проекта встречается в неожиданных местах | authorized_keys, sudoers, юниты, drop-in, конфиг зон | см. §4.4 «где упоминается имя» |
