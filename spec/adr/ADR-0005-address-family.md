# ADR-0005. Семейство адресов выбирается, а не угадывается

- Статус: принято
- Контекст: spec/zones.md §3.5, ADR-0006 основного проекта (вход через промо-VPS)

## Проблема

Если имя отдаёт и `A`, и `AAAA`, клиент сам решает, куда идти. В условиях
фильтрации трафика это опасно: РКН может резать IPv4 и не резать IPv6, и
тогда значительная часть программ (старые клиенты, `curl -4`, скрипты без
Happy Eyeballs) уйдёт по заблокированному адресу и останется ни с чем —
хотя IPv6-путь работал бы.

Формулировка «у хоста два адреса, публикуем оба» верна технически, но
ошибочна по смыслу: DNS-ответ — это инструкция клиенту, а не инвентаризация.

## Варианты

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| Публиковать оба | «честно» | клиент выбирает вслепую; фильтр ломает доступ | отвергнут |
| Только IPv6 везде | предсказуемо | имена недоступны для IPv4-only клиентов | не универсален |
| **Выбор через `FAMILY`** | явно, по контуру, меняется без кода | требует дисциплины в конфиге | **принят** |

## Решение

Переменная `FAMILY` в конфиге разработчика (`~/.host2ns/config`) — список
токенов через запятую:

| Значение | Что публикуется |
| --- | --- |
| `ipv6` | только `AAAA` |
| `ipv4` | только `A` |
| `nat` | `A` с адресом, который видит NS в `SSH_CONNECTION` |

По умолчанию — `ipv6,ipv4`. Отправитель получает значение при установке
(`--family`) и сохраняет его в `/etc/<NAME>/family`; юнит и ручной запуск
читают файл.

Для контура, где IPv4 фильтруется, — `ipv6`; для шлюза с публичным IPv4 —
`ipv4`; для хоста за NAT — `nat` (обычно `nat,ipv6`).

## Последствия

Проще: поведение DNS перестаёт зависеть от того, что «само нашлось» на
интерфейсе; можно осознанно отдать имя только в одну сеть.
Сложнее: появился ещё один параметр конфигурации, и его надо помнить при
добавлении хоста с публичным IPv4.

## Что заставит пересмотреть

1. Появится имя, которому нужны оба семейства намеренно — тогда понадобится
   выбор на уровне имени, а не контура.
2. Фильтрация станет нестабильной (то есть, то нет) — тогда `FAMILY` не
   спасёт, понадобится внешняя точка входа в обеих сетях.
## Дополнение: политика на отдельный хост

Одно значение на контур оказалось недостаточно: входной шлюз и площадка живут
в разных условиях. Например, шлюз должен принимать IPv4-клиентов (у него есть
публичный адрес), а площадка — нет (её IPv4 фильтруется).

Поэтому добавлен необязательный файл `~/.host2ns/policy`:

    # <хост>  ipv6|ipv4|nat[,<...>]
    gw.example.ru   ipv4
    app.example.ru  ipv6
    home.example.ru nat,ipv6

Правила разбора:

| Наличие | Поведение |
| --- | --- |
| файла нет | все хосты получают `FAMILY` из config |
| хост есть в файле | берётся его значение |
| хоста нет в файле | берётся `FAMILY` из config |

Почему отдельный файл, а не третья колонка в `hosts`: реестр имён и политика
меняются по разным поводам. Смешивать их в одной строке — значит заставлять
править список имён при изменении политики и наоборот.

## Дополнение: список токенов и NAT

Одно значение `FAMILY` не выражает хост за NAT: у него может быть одновременно
настоящий IPv6 и внешний IPv4 роутера. Поэтому значение — **список через
запятую**:

| Токен | Что публикует |
| --- | --- |
| `auto` / `both` (историческое, убрано) | свои IPv6 и IPv4, если есть |
| `ipv6` / `v6` (псевдоним убран) | только свои IPv6 |
| `ipv4` / `v4` (псевдоним убран) | только свои IPv4 |
| `nat` | IPv4, который видит NS (публичный адрес роутера) |

Примеры: `ipv6`, `nat`, `ipv6,nat`.

**Откуда берётся NAT-адрес.** Приёмник читает `SSH_CONNECTION`, переменную
ставит sshd после аутентификации: первое поле — адрес клиента, каким его
видит NS. Для хоста за NAT это публичный адрес роутера. Внешние сервисы
вида `ipify` не нужны, и хост может не иметь выхода в IPv4 вообще.

**Приватный IPv4 по-прежнему не публикуется.** Токен `nat` заменяет его
адресом точки входа; `auto` и `ipv4` берут только глобальные адреса
интерфейсов.

**Ограничение.** Если хост приходит на NS через бастион или прокси, `nat`
опубликует адрес бастиона. Для таких хостов токен не указывают.

## Дополнение: три токена

Набор сокращён до трёх значений, по умолчанию — `ipv6,ipv4`:

| Токен | Что публикует |
| --- | --- |
| `ipv6` | свои IPv6-адреса |
| `ipv4` | свои IPv4-адреса |
| `nat` | IPv4, который видит NS (публичный адрес роутера) |

`ipv6,ipv4` — то же, что раньше называлось `auto`: публиковать всё, что есть.
`nat,ipv6` — особый случай: свой IPv6 плюс внешний IPv4 роутера.

Псевдонимы (`auto`, `both`, `v4`, `v6`) убраны: одно значение — один смысл,
лишние синонимы только создают вопросы «а чем это отличается».
