# ADR-0002. Push по SSH, а не внешний DDNS-провайдер

- Статус: принято
- Контекст: `spec/problem.md` §1.2

## Проблема

Нужно обновлять имена при смене адреса. Варианты: внешний DDNS-провайдер,
RFC 2136, собственный push.

## Варианты

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| Внешний DDNS | ничего не администрировать | токены, чужие зоны, ограничения API | отвергнут |
| RFC 2136 | стандарт | NSD не поддерживает | отвергнут |
| Push по SSH | ключ уже есть, нет нового секрета | свой код сопровождения | **принят** |

## Решение

Хост инициирует соединение и передаёт состояние по stdin. На NS-хосте команда
приёма закреплена в `authorized_keys`, пароль не используется.

## Последствия

Плюс: нет токенов и ротации; ключ живёт столько же, сколько хост.
Минус: код наш — при отказе чинить нам.

## Что заставит пересмотреть

1. Понадобятся динамические обновления в реальном времени — тогда BIND/Knot.
2. Появится требование отдавать имена наружу через API провайдера.
