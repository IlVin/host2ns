# ADR-0004. Зоны — производное конфига, а не рантайм-регистрация

- Статус: принято
- Контекст: spec/architecture.md §2.3, spec/pitfalls.md §6.1

## Проблема

NSD умеет и `nsd-control addzone`, и чтение конфигурации. Первый вариант
казался проще: не нужно пересобирать конфиг при каждом изменении.

## Варианты

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| `addzone` по одной зоне | без перезаписи конфига | второй аргумент — pattern, не путь; состояние в рантайме теряется при перезапуске | отвергнут |
| **Генерация конфига из состояния** | переживает перезапуск, один источник истины | нужно переписывать конфиг и перечитывать | **принят** |
| RFC 2136 | стандарт | NSD не поддерживает | отвергнут |

## Решение

Источник истины — каталог `/var/lib/<NAME>/state`. Из него генерируются файлы
зон и конфиг `/etc/nsd/nsd.conf.d/10-<NAME>-zones.conf`. Рантайм-список
`zone.list` обнуляется при каждой генерации.

Применение: `nsd-control reconfig` (состав зон) → `nsd-control reload`
(данные зон) → при неудаче `systemctl restart nsd`.

## Последствия

Плюс: состояние переживает перезагрузку, зоны воспроизводимы из каталога.
Минус: каждое изменение — перезапись файлов и перечитывание; при большом
числе зон станет заметно.

## Что заставит пересмотреть

1. Появятся сотни зон — понадобится инкрементальное применение.
2. NSD заменят на BIND/Knot — можно перейти на RFC 2136.
