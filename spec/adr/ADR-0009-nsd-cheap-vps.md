# ADR-0009. NSD — лёгкий авторитативный сервер для дешёвого VPS

- Статус: принято
- Контекст: ADR-0004, ADR-0007, `spec/bootstrap-nsd.md`, `spec/install.md`

## Проблема

NS должен жить на VPS. Хочется самый дешёвый тариф (512 MB/1 GB), без
отдельной БД и без сложного сопровождения: зоны небольшие, трафик —
обычные DNS-запросы, рекурсии нет.

## Варианты

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| BIND | стандарт, RFC 2136, DNSSEC, secondary | тяжелее по памяти, сложнее конфиг, больше поверхности | отвергнут |
| Knot | быстрый, RFC 2136, DNSSEC | тяжелее NSD, свои инструменты | отвергнут |
| PowerDNS + БД | API, динамика | БД, больше памяти/сопровождения | отвергнут |
| **NSD** | малый footprint, статические зоны, пакет, `nsd-control`, `nsd-checkconf` | нет RFC 2136, нет online DNSSEC | **принят** |

## Решение

NSD; зоны генерируются из состояния (`zonegen`), а не правятся в рантайме;
применение — `nsd-control reconfig` + `reload`; проверка — `nsd-checkconf`;
пакет Ubuntu/Debian; `bootstrap-nsd`; конкретные адреса; `systemd-resolved`
не отключается.

## Последствия

Проще: дешёвый VPS, минимум памяти, нет БД, статические зоны, простой
`nsd.conf`, `nsd-control`.
Сложнее: нет RFC 2136 — зоны перегенерируются целиком; нет online-подписи
DNSSEC; один primary (второй NS — отдельная задача).

## Что заставит пересмотреть

1. Понадобится динамика/RFC 2136 или API.
2. Понадобится online DNSSEC/secondary/anycast.
3. Память перестанет быть ограничением, а BIND/Knot дадут нужные функции.
