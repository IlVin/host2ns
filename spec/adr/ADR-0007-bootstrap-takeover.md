# ADR-0007. Бутстрап NSD — транзакционный takeover, а не безусловный restart

- Статус: принято
- Контекст: `spec/bootstrap-nsd.md`, `spec/install.md` §4.4, `spec/pitfalls.md` §6.1

## Проблема

`bootstrap-nsd` должен и ставить NSD на чистый хост, и обновлять уже
работающий. Первый коммит проекта (`a1c611d`) делал
`systemctl is-active nsd || systemctl start nsd`: работающий NSD не
перезапускался, а невалидный `00`-конфиг вообще не проходил
`nsd-checkconf`. Поэтому прежняя установка (main-конфиг и старые зоны)
продолжала работать.

Коммит `96b0544` заменил это на безусловный `systemctl restart nsd`, чтобы
применять новый конфиг. На существующем NS это остановило рабочий NSD, а
новый не смог занять адрес: сначала wildcard конфликтовал с
`systemd-resolved`, затем конкретный адрес дублировался в старом main и
новом `00`, а старый процесс мог жить в другом network namespace. Итог —
DNS лёг, хотя «до этого работало».

## Варианты

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| Никогда не перезапускать работающий NSD (как `a1c611d`) | безопасно | новый конфиг/зоны не применяются; обновления нет | отвергнут как единственное поведение |
| Безусловный `restart` (как `96b0544`) | применяет конфиг | останавливает рабочий DNS; нет отката; конфликты адресов | отвергнут |
| Остановить и запустить без поиска старого | применяет конфиг | старый процесс в netns/вне unit остаётся; второй bind падает | отвергнут |
| **Транзакционный takeover** | применяет конфиг; старый DNS не теряется; есть откат | краткий разрыв DNS на время старта | **принят** |

## Решение

Перед запуском `bootstrap-nsd`:

1. Сравнивает сгенерированный конфиг с текущим (`cmp`); если не изменился и
   управляемый NSD активен — не трогает его.
2. Сохраняет старый `00`-конфиг (для отката).
3. Ищет старый NSD:
   - `systemctl stop nsd` (управляемый unit);
   - `ss` в host и во всех netns (`/proc/*/ns/net` через `nsenter`);
   - `pgrep -f` по командной строке + проверка `/proc/PID/exe`; NSD
     переименовывает потоки в `nsd: main`/`nsd: server 1`, поэтому
     `pgrep -x nsd` не годится.
4. Останавливает найденные NSD, ждёт освобождения адресов; чужой DNS
   (named/dnsmasq/unbound) не убивает — сообщает владельца и не стартует.
5. Проверяет дубли `ip-address` (`uniq -d`); при дубле откатывает конфиг и
   завершается ошибкой.
6. `reset-failed`, `start`; если NSD не поднялся — возвращает старый конфиг,
   запускает его и сообщает, что работает старая версия.

Диагностика владельца 53 — `make nsd-who HOST=<ns>` (`--who-has-53`): обход
всех netns, строки `ss` с PID. Это нужно, когда host-`ss` пуст, а bind
падает.

## Последствия

Проще: обновление существующего NS стало предсказуемым; старый DNS не
остаётся «за кадром»; при неудаче возвращается рабочая конфигурация.
Сложнее: краткий разрыв DNS при смене адресов/конфига; нужен поиск в netns;
нельзя автоматически убить чужой DNS — это осознанное ограничение.

## Что заставит пересмотреть

1. NSD научится менять адреса без рестарта (reload конфига).
2. Появится внешний оркестратор, который сам останавливает старый DNS.
3. Старый DNS окажется не NSD, а сервисом, которым владеет другой проект —
   тогда takeover должен быть отдельной явной операцией.
