# 2. Architecture

## 2.1. Компоненты

| Компонент | Где | Роль |
| --- | --- | --- |
| отправитель (`host2ns.sh`) | каждый хост | собирает адреса и имена, шлёт по SSH при изменении |
| приёмник (`receiver.sh`) | NS-хост | проверяет имена, пишет состояние, применяет зоны |
| генератор (`zonegen.sh`) | NS-хост | рендер зон и конфига NSD; общий для приёмника и восстановления |
| восстановитель (`rebuild.sh`) | NS-хост | зоны из состояния до старта NSD |
| NSD | NS-хост | отдаёт зоны по 53; лёгкий, для дешёвого VPS (ADR-0009) |

## 2.2. Поток

    таймер → отправитель → ssh → приёмник → состояние → зоны → конфиг → reconfig + reload

## 2.3. Состояние

    /var/lib/<NAME>/state/<зона>/<id-хоста>   строки "<запись> <адрес>"

Набор декларативен: присланное заменяет прежнее, пустой набор удаляет.
Замена действует на **все** зоны хоста: файл в зоне, которую он больше не
объявляет, удаляется. Опустевший каталог зоны не обслуживается и удаляется —
пустая зона не должна попадать в конфиг NSD.
Источник истины — это состояние, а не файлы зон: зоны всегда выводятся из него.
Хоста, которого больше нет в реестре, никто не опрашивает, поэтому его файлы
удаляет `make prune`: она сверяет id в состоянии с реестром и присылает
пустой набор.
Если применить зоны не удалось (NSD не перечитал данные), приёмник завершается
с ошибкой: отправитель не сохраняет состояние и повторит публикацию через
таймер. Молчаливый «ok» при неработающем NSD недопустим.

Рядом лежит `/var/lib/<NAME>/last` — время последней публикации. Его очищает
установка отправителя, чтобы после `prune` или восстановления NS данные
перепубликовались. `make status` читает `last` и показывает свежесть.

## 2.4. Инварианты

1. Файлы зон — производное; руками не правятся.
2. Конфиг NSD перечисляет зоны явно; рантайм-список (`zone.list`) пуст.
3. Генерация зон выполняется **вне** песочницы `nsd.service`.
4. Приватные IPv4 в зону не попадают.
5. Файл зоны и конфиг NSD заменяются атомарно: временный файл рядом с
   целевым, затем `mv`. Файлы зон — 644, иначе NSD их не прочитает.
6. `bootstrap-nsd` не дублирует `ip-address` из main/чужих drop-in'ов и
   проверяет дубли (`uniq -d`); дубль — ошибка, а не «второй слушатель».
7. `bootstrap-nsd` не убивает чужой DNS: останавливает только NSD; при
   чужом владельце 53 сообщает и не стартует.
8. `systemd-resolved` не отключается; NSD слушает конкретные адреса хоста
   и loopback.
9. `make status` не показывает ошибки `dig` как адреса; `-` означает
   отсутствие записи/ответа, а не текст ошибки.

## 2.5. Установщики

Код установки отделён от данных двумя шагами:

| Шаг | Пароль | Что делает |
| --- | --- | --- |
| `make bootstrap-host HOST=x` | да | по SSH кладёт скрипты в `/usr/local/lib/<NAME>` и создаёт правило sudo |
| `make host2ns` | нет | вызывает `sudo -n /usr/local/bin/<NAME>-install.sh sender|ns` |

Отдельно `make bootstrap-nsd HOST=ns` по SSH ставит и настраивает NSD на
указанном хосте: это подготовка DNS-сервера, а не установка кода проекта.
Он не перезапускает существующий NSD вслепую: сравнивает конфиг, сохраняет
старый, ищет старый unit/процесс (в том числе в другом netns), останавливает
только NSD, проверяет дубли адресов и откатывается при неудаче (ADR-0007,
ADR-0008). Диагностика владельца 53 — `make nsd-who HOST=ns`.
У регистратора — только `NS`-записи и glue; зоны — на своём NSD, не в
UI/API провайдера (ADR-0010).

`bootstrap-host` создаёт команду, разрешённую без пароля: диспетчер на два
действия. Код берётся из root-каталога, поэтому подменить его через `/tmp`
нельзя; `--src` диспетчер не принимает. Параметры (`NAME`, `BASE`, `--user`)
проверяются до root-действий: имя и база не должны уводить пути из
`/etc`, `/var/lib` и `/usr/local`. Второе правило NOPASSWD —
приёмник, оно ограничено forced command в `authorized_keys`.
Обновление кода требует пароля — это осознанно.

## 2.6. Политика семейства

`FAMILY` в конфиге разработчика задаёт набор токенов (`ipv6`, `ipv4`, `nat`) для
всех хостов; `~/.host2ns/policy` перекрывает его для отдельных хостов. Значение
передаётся при установке и сохраняется в `/etc/<NAME>/family`; отправитель читает
файл — и под юнитом, и при ручном запуске.

## 2.7. Наблюдение: `make status`

`make status` — приёмочная проверка, а не управление. Он показывает:

- зоны, которые реально обслуживает NS (по `zone.list`/`конфигу через SSH);
- имена из состояния и ответы NS (`dig AAAA`/`A`), политику из
  config/policy;
- записи в состоянии по зонам;
- время последней публикации из `/var/lib/<NAME>/last`.

Ответы `dig` фильтруются: `;; communications error...` — ошибка, а не адрес;
в таблице будет `-`. `-` в IPv4/IPv6 означает отсутствие записи или ответа,
а не «политика не задана».

`ИТОГ: всё на месте и соответствует политике` — у всех имён есть записи,
которые требует политика (`ipv6` — только AAAA; `nat,ipv6` — AAAA и A;
`ipv4,ipv6` — оба; `nat` — A), зоны совпадают с состоянием, публикация не
просрочена. Иначе — предупреждения и ненулевой код.
