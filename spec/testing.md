# 7. Проверка

## 7.1. Локально

    make check

Генерирует зоны во временных каталогах и проверяет: синтаксис всех скриптов,
файлы созданы, записи на месте, конфиг содержит блоки зон, серийник — epoch,
файлы зон — 644 и не оставляют временных файлов. Отдельно проверяются:

- приёмник: nat без своих адресов, пустой набор, переезд имени между зонами,
  удаление опустевшей зоны, строгая проверка адресов, ошибка NSD видна снаружи;
- отправитель: выбор стабильного адреса, FAMILY, отсутствие лишних отправок,
  смена NS, пустой набор без адресов;
- установщики: комплект файлов, валидация аргументов, `--print-user`, LIB из
  имени диспетчера;
- `authorize.sh`, `prune.sh`, `publish.sh` и `status.sh` — на фейковых
  `ssh`/`dig`/`ip`;
- конфиг NSD — настоящим `nsd-checkconf`, если он установлен.

Хосты и root не нужны.

## 7.2. На стенде

    make status

Показывает зоны на NS, имена с адресами и **политикой**, содержимое состояния и
время последней публикации с каждого хоста. Отдельно сверяет факт с политикой:

| Проверка | Сообщение |
| --- | --- |
| IPv6 есть, а политика без `ipv6` | `! IPv6 есть, но политика не включает ipv6` |
| IPv4 есть, а политика без `ipv4`/`nat` | `! IPv4 есть, но политика не включает ipv4/nat` |
| политика `nat`, а IPv4 нет | `! политика ждёт nat, но IPv4 нет` |
| политика `ipv4` (без `nat`), а A нет | `! политика ждёт ipv4, но A нет` |
| политика `ipv6`, а AAAA нет | `! политика ждёт ipv6, но AAAA нет` |

Код выхода 1, если есть любое замечание. `ИТОГ: всё на месте и
соответствует политике` — замечаний нет.

Ответы `dig` фильтруются по формату IP: `;; communications error...` —
ошибка, а не адрес; в таблице будет `-`, а не текст ошибки. Это проверяется
фейковым `dig` с `DIG_FAIL=1`: статус не должен выдавать ошибку за IPv4/IPv6
и должен завершиться кодом 1.

Пример успешной приёмки (`FAMILY=ipv6`, у `gw` политика `ipv4,ipv6`):

    DOMAIN                  POLICY       IPv6                       IPv4
    ssh.h.example.ru        nat,ipv6     2a02:2168:...:1c0          95.84.164.156
    hub.d.plb.example.ru    ipv6         2a02:2168:...:2113         -
    gw.d.plb.example.ru     ipv4,ipv6    2a00:b700::4:3ec           46.17.42.198
    ...
    ИТОГ: всё на месте и соответствует политике

В состоянии при этом могут быть старые имена (`yach-*`) и имя NS
(`nsiv77mskru`); они видны в статусе, пока их не уберёт `make prune`.

## 7.3. Приёмка

1. `make host2ns` проходит без паролей после `bootstrap-host` на каждом
   хосте **и** `bootstrap-nsd HOST=<ns>` на NS; ключ хоста разрешается на NS
   автоматически.
2. `dig AAAA <домен> @<NS>` отдаёт адрес; `dig A` тоже, если политика включает
   `ipv4` или `nat`.
3. Перезагрузка NS-хоста: зоны восстанавливаются до старта NSD
   (`host2ns-zones.service` + `Before=nsd`).
4. Перезагрузка отправителя: таймер публикует через 30 секунд.
5. Публикация без перезапуска NSD: после `make host2ns` новые записи видны
   сразу (`nsd-control reconfig` + `reload`).
6. `make restore` перегенерирует зоны и перечитывает NSD.
7. Хост, убранный из реестра, удаляется `make prune`; его имена исчезают.
8. `BASE` из `/etc/<NAME>/base` совпадает с доменом в `dig`.
9. `make status` печатает `ИТОГ: всё на месте и соответствует политике`:
   `ipv6`-имена имеют только AAAA, `nat,ipv6` — AAAA и A,
   `ipv4,ipv6` — оба; зоны совпадают с состоянием; `last` не просрочен.
10. Статус при недоступном DNS не показывает `;; communications error` как
    адрес: в таблице `-`, код выхода 1.
11. `bootstrap-nsd` на существующем NS: старый main содержит `ip-address`,
    новый `00` его не дублирует; `uniq -d` пуст; NSD стартует и слушает
    адрес один раз.
12. Старый NSD (unit неактивен, процесс в netns) останавливается takeover'ом;
    `make nsd-who` показывает владельца; при неудаче нового конфига
    возвращается старый.
13. Старый `10-yach-zones.conf` не дублирует `10-host2ns-zones.conf`: один
    конфиг на проект; `nsd-checkconf`/NSD не ругаются на дубль зоны.

## 7.4. Что проверялось вручную

- перезагрузка NS-хоста — имена отвечают;
- NAT-хост: `A` содержит публичный адрес роутера из `SSH_CONNECTION`;
- политика `ipv6` на хосте с публичным IPv4 — записи `A` нет;
- `sudo -n <диспетчер>` работает без пароля, `sudo -n /bin/sh` — нет;
- существующий NS с main-`ip-address` и старым NSD: `bootstrap-nsd` не
  дублирует адрес, останавливает старый NSD (в том числе в netns), поднимает
  управляемый; `make nsd-who` показывает владельца; `make status` —
  `ИТОГ`;
- `ss` пуст, а bind падает: `nsd-checkconf -o ip-address` показывает дубль
  main+`00`; после `main_ip_addrs` NSD стартует;
- SSH-проброс привилегированного порта: слушатель был бы виден в `ss` как
  `sshd`; пустой `ss` — это дубль конфига, а не проброс;
- статус на `FAMILY=ipv6`: `ssh`/`backup` — `nat,ipv6` (AAAA+A),
  `hub`/`tg`/`ca` — `ipv6` (AAAA), `gw` — `ipv4,ipv6` (оба),
  `ИТОГ: всё на месте и соответствует политике`.

## 7.5. Стенд на Docker

Проверка на «голых» Ubuntu 24.04 и Debian 12: три гостя с systemd в одной сети —
NS, отправитель и рабочая машина. У каждого гостя свой пользователь `ilvin` с
sudo и ключом оператора; NS и отправитель адресуются по именам из `/etc/hosts`.

    make bootstrap-host HOST=<ns>      # на NS по SSH, нужен пароль
    make bootstrap-nsd HOST=<ns>       # на NS по SSH, нужен пароль
    make bootstrap-host HOST=<host>    # на каждом отправителе по SSH, нужен пароль
    make host2ns                       # на рабочей машине
    make status
    make restore
    make prune

Проверено: install → publish → `dig` A/AAAA → `make status` → `make restore` →
`make prune` → повторное добавление хоста. `bootstrap-nsd` проверен на
контейнере с активным `systemd-resolved`: NSD стартует рядом с ним. Отдельно
проверен takeover: `nsd.service` неактивен, а на адресах висит старый NSD
(потоки `nsd: main`/`nsd: server 1`) — скрипт находит PID через `ss`,
останавливает старый и запускает управляемый; повторный запуск не меняет PID;
изменение конфига перезапускает. Отдельно проверено, что старый NSD в другом
network namespace не виден в `ss`, но находится через `pgrep -f` и
останавливается. `--who-has-53` проверен там же: host-`ss` пуст, а
диагностика печатает netns и PID-ы старого NSD. Отдельно проверено, что
`ip-address`, уже заданный в main-конфиге, не дублируется в `00`:
старый main + `00` дают `EADDRINUSE`, после исправления NSD стартует и
слушает адрес один раз. `make status` на стенде проверен с `FAMILY=ipv6`:
`nat,ipv6` — AAAA+A, `ipv6` — только AAAA, `ipv4,ipv6` — оба; итог
`всё на месте`. При погашенном NSD статус печатает `-`, а не
`;; communications error`, и завершается 1. Старый `10-yach-zones.conf`
не дублирует `10-host2ns-zones.conf` (один конфиг на проект); старые имена
`yach-*` убирает `make prune`, статус показывает их до этого. На Debian 12
отдельно проверены `bootstrap-nsd`, `install-ns`
и приёмник (NSD 4.6.1); на Ubuntu 24.04 — вся цепочка, включая ключи и таймер
(NSD 4.8.0).

Docker держит `127.0.0.11:53`, на Ubuntu ещё `systemd-resolved` на
127.0.0.53/54. Это не мешает: `bootstrap-nsd` биндит конкретные адреса `eth0`
и loopback, а не `0.0.0.0`.
