# 5. Бутстрап NSD

`make bootstrap-nsd HOST=<ns>` — ставит и настраивает NSD на указанном хосте
по SSH. Без `HOST` команда не выполняется. `sudo` запускается на удалённой
стороне, отдельный `sudo make` не нужен.

Перед этим на NS нужен `make bootstrap-host HOST=<ns>`: этот скрипт ставит
только NSD, а диспетчер установки и приёмник приходят из `bootstrap-host`.

Локальная машина тоже указывается явно, например `HOST=ilvin@localhost`
(на ней должен быть `sshd`). `make` копирует `scripts/bootstrap-nsd.sh` на
хост через `scp` и запускает его под sudo по SSH — вручную ничего копировать
не нужно.

## 5.1. Что делает

1. Ставит пакет `nsd`, если его нет. Ошибка `apt-get update` из-за чужого
   репозитория (просроченный ключ, 404 на PPA) не останавливает установку:
   обновление предупреждает, дальше пробуем поставить `nsd`; если и это не
   вышло — понятная ошибка.
2. Создаёт `/var/lib/nsd/zones`, владелец `nsd:nsd`.
3. Пишет `/etc/nsd/nsd.conf.d/00-<NAME>.conf`: `ip-address` только для
   адресов, которых ещё нет в main-конфиге и чужих drop-in'ах (иначе NSD
   биндит адрес дважды и падает с `EADDRINUSE`, а в `ss` после падения
   пусто); реальные глобальные адреса (без docker/br/veth и
   temporary/deprecated/tentative), плюс `127.0.0.1`/`::1`; `zonesdir`;
   `remote-control`. Не `0.0.0.0`: wildcard конфликтует с
   `systemd-resolved` на 127.0.0.53/54. Конфиг печатается тем же `printf`,
   что проверяется в `make check`.
4. Создаёт ключи `nsd-control`, если их нет.
5. `nsd-checkconf`, проверка `zonesdir` через `include` из
   `/etc/nsd/nsd.conf` и проверка дублей `ip-address` (`uniq -d`); при
   дубле старый конфиг возвращается.
6. Сохраняет старый `00`, останавливает старый NSD (управляемый unit и
   процессы в любых netns), снимает `reset-failed`, запускает управляемый;
   при неудаче возвращает старый конфиг и запускает его.

## 5.2. Почему так

| Решение | Причина |
| --- | --- |
| зоны только через конфиг, не через `nsd-control addzone` | `addzone` требует имя pattern, а не путь; промах даёт пустую зону |
| `zonelistfile` в `/run/nsd` | в `/var/lib/nsd` файл принадлежит root и не читается службой |
| генерация зон отдельным юнитом | юнит должен отработать **до** NSD; в старых пакетах песочница `nsd.service` не давала писать в `/var/lib/nsd`. В актуальных пакетах есть `ReadWritePaths=/var/lib/nsd`, но полагаться на это нельзя |
| `ip-address:` с конкретными адресами, а не `listen:` | `listen` — синтаксис BIND/Knot; у NSD `ip-address:` |
| конкретные адреса, не `0.0.0.0` | `systemd-resolved` слушает 127.0.0.53/54; wildcard-биндинг с ним конфликтует |
| не дублировать `ip-address` из main | старый main может уже содержать адрес; второй bind даёт `EADDRINUSE`, а `ss` пуст; `main_ip_addrs` исключает адреса main, `uniq -d` проверяет дубли |
| NSD, а не BIND/Knot/PowerDNS | малый footprint, дешёвый VPS, статические зоны, без БД (ADR-0009) |
| не править зоны в UI/API провайдера | хрупко/сложно, нет состояния/политики/аудита; у регистратора только `NS`/glue, зоны на NSD (ADR-0010) |
| остановить старый NSD, а не просто `restart` | старый процесс может быть вне unit/в другом netns; второй bind падает | `ss` + `pgrep -f` + `/proc/PID/exe`; stop; wait; start |
| не убивать чужой DNS | named/dnsmasq/unbound не наши; их остановка — чужая авария | при чужом владельце 53 скрипт сообщает и не стартует |
| диагностика `nsd-who` | host-`ss` пуст, если сокет в netns; нужен ответ, а не догадка | обход `/proc/*/ns/net` + `nsenter` |
| `remote-control: control-enable: yes` явно | иначе `nsd-control` может быть выключен и каждая публикация уйдёт в полный `systemctl restart` |
| зоны не пишутся «на место» вручную | файлы — производное от состояния |
| база имён — в `/etc/<NAME>/base`, не в конфиге NSD | NSD базу не читает; файл нужен приёмнику и генератору |

## 5.3. Повторный запуск

Скрипт можно запускать на одном и том же хосте много раз:

- если `nsd` уже установлен, `apt-get` не вызывается;
- сгенерированный конфиг сравнивается с текущим (`cmp`); при совпадении
  работающий NSD **не перезапускается**;
- `systemctl reset-failed nsd` снимает start-limit после неудачных стартов;
- NSD слушает конкретные адреса хоста и loopback, поэтому `systemd-resolved`
  на 127.0.0.53/54 не мешает; системный резолвер менять не нужно;
- если NSD уже работает (управляемый unit или процесс старой установки),
  скрипт останавливает его перед запуском. `pgrep -x nsd` для этого не
  годится: NSD переименовывает потоки в `nsd: main`, `nsd: server 1`,
  `nsd: xfrd`. PID берутся из `ss` **и** из таблицы процессов
  (`pgrep -f`): старый NSD может держать адрес в другом network namespace
  и не быть виден в `ss`; проверяется `/proc/PID/exe`;
- адреса, уже заданные в main или чужих drop-in'ах, в `00` не
  дублируются: NSD биндит такой адрес дважды и падает с `EADDRINUSE`, а
  `ss` после падения пуст; перед стартом есть проверка `uniq -d`. Это не
  «второй слушатель», а дубль в собственном конфиге;
- перед заменой конфига старый файл сохраняется. Если новый не проходит
  `nsd-checkconf`, не подхватывает `zonesdir`, содержит дубль `ip-address`
  или NSD не поднялся, старый конфиг возвращается и запускается — DNS не
  остаётся лежать;
- старый NSD ищется и в host-`ss`, и в `ss` каждого netns, и по
  `pgrep -f`; чужие DNS (named/dnsmasq/unbound) не убиваются — выводится
  владелец и хвост journal;
- владельца 53 можно посмотреть отдельно: `make nsd-who HOST=<ns>`
  (§5.4).

Повторный запуск после неудачного старта поднимает NSD: конфиг становится
совместимым, start-limit снят.

**Почему это важно.** Первый коммит (`a1c611d`) делал
`is-active nsd || start nsd` и не перезапускал работающий NSD; его
невалидный `00` вообще не проходил `nsd-checkconf`. Поэтому старая
установка (main-конфиг и зоны) продолжала работать — «работало» означало
«скрипт не вмешивался». Коммит `96b0544` заменил это на безусловный
`systemctl restart`: старый NSD был остановлен, а новый не смог занять
адрес — сначала wildcard конфликтовал с `systemd-resolved`, затем
конкретный адрес дублировался в старом main и новом `00`, а старый процесс
мог жить в другом netns. Обновление существующей установки — это takeover с
откатом, а не «поставить поверх» (ADR-0007, ADR-0008).

## 5.4. Кто держит 53

`make nsd-who HOST=<ns>` копирует скрипт и запускает `--who-has-53`. Он
обходит `/proc/*/ns/net`, входит в каждый network namespace через
`nsenter` и печатает строки `ss` с PID-ами. Обычный `ss` на хосте видит
только host netns: если 53 держит старый DNS в контейнере/unit'е, там его
не будет.

Пример:

```text
netns 4026534939 (pid 358)
UNCONN 0 0 127.0.0.1:53 0.0.0.0:* users:(("nsd: server 1",pid=365,fd=3),("nsd: main",pid=364,fd=3),("nsd: xfrd",pid=358,fd=3))
```

Без скрипта то же самое: `sudo ss -lntup 'sport = :53'` (host),
`sudo lsns -t net` и
`sudo nsenter -t <pid> -n ss -lntup 'sport = :53'` (нужный netns).

Если `ss` пуст **и в host, и во всех netns**, а `nsd` всё равно падает с
`Address already in use`, владельца-процесса нет: адрес продублирован в
конфиге NSD. Проверка:

    sudo nsd-checkconf -o ip-address /etc/nsd/nsd.conf
    sudo grep -Rn 'ip-address' /etc/nsd/nsd.conf /etc/nsd/nsd.conf.d/

Дубль лечится `main_ip_addrs` (ADR-0008), а не остановкой процессов.

SSH-проброс привилегированного порта (`ssh -R 53:...`, `GatewayPorts`,
`ip_unprivileged_port_start=0`) теоретически возможен, но его слушатель был
бы виден в `ss` как `sshd`/`ssh`. Пустой `ss` указывает на дубль в
конфиге, а не на проброс.
