# host2ns

Публикация имён хостов в собственном сервере имён. Хост присылает свои адреса
по SSH; NS-хост складывает их в состояние, генерирует файлы зон и применяет
конфигурацию NSD.

Зачем: IPv6-префикс меняется, часть хостов стоит за NAT, а имена должны всегда
указывать на рабочий адрес. Провайдеры DDNS требуют токенов и отдают имена
наружу; здесь имя живёт в своей зоне, а доступ — по SSH-ключу, который и так есть.

## Как это работает

    хост: таймер раз в 10 минут
      → адрес изменился? → ssh на NS: host <id>, policy <...>, <имя> <адрес>...
    NS: приёмник → состояние → файлы зон → конфиг NSD → reconfig + reload

Модель имён: `<запись>.<зона>` → `<зона>.<BASE>`. Пример при `BASE=example.ru`:
`tg.d.plb` даёт зону `plb.example.ru` и запись `tg.d`. Полное имя —
`tg.d.plb.example.ru`.

## Быстрый старт

    cp config.example ~/.host2ns/config      # NS, BASE, FAMILY
    cp registry.example ~/.host2ns/hosts     # хосты и их имена
    cp policy.example ~/.host2ns/policy      # необязательно: политика по хостам

    make bootstrap-host HOST=<алиас>         # один раз на каждый хост, включая NS
    make bootstrap-nsd                       # один раз на NS, нужен пароль
    make host2ns                             # без паролей: установка и публикация
    make status                              # зоны, имена, политика

`bootstrap-host` нужен и NS-хосту: `bootstrap-nsd` ставит только NSD, а
диспетчер установки и приёмник кладёт `bootstrap-host`. Без него `make host2ns`
на NS упадёт с подсказкой.

Ключ каждого отправителя разрешается на NS сам: `make host2ns` кладёт его в
`authorized_keys` с forced command приёмника (`make authorize HOST=x` — если
нужно повторить вручную).

## Семейство адресов

Управляется списком токенов через запятую:

| Токен | Что публикует |
| --- | --- |
| `ipv6` | свои IPv6-адреса |
| `ipv4` | свои IPv4-адреса |
| `nat` | IPv4, который видит NS (публичный адрес роутера) |

По умолчанию `ipv6,ipv4` — публиковать всё, что есть у хоста.

    FAMILY=ipv6,ipv4                        # в config — для всех хостов
    echo "tower.example.ru nat,ipv6" >> ~/.host2ns/policy   # исключение

Токен `nat` нужен хостам за роутером: их собственный IPv4 приватный, а NS
видит публичный адрес роутера в `SSH_CONNECTION`. Подробности —
`spec/adr/ADR-0005-address-family.md`.

## Файлы

| Путь | Что это |
| --- | --- |
| `GNUmakefile` | входные точки: host2ns, status, check, bootstrap-host, bootstrap-nsd, restore |
| `scripts/` | отправитель, приёмник, генерация зон, установка, статус |
| `systemd/` | объяснение юнитов и порядка запуска |
| `spec/` | зачем, как устроено, грабли, проверка, ADR |
| `*.example` | образцы конфигурации разработчика (в репозиторий не коммитятся) |

## Где что лежит на хосте

    /etc/<NAME>/key         ключ SSH (400, владелец — пользователь)
    /etc/<NAME>/names       имена хоста
    /etc/<NAME>/id          идентификатор хоста
    /etc/<NAME>/family      политика семейства
    /var/lib/<NAME>/last    последняя отправленная строка (отправитель)
    /var/lib/<NAME>/state/  состояние по зонам (NS)
    /usr/local/lib/<NAME>/  код установщиков (root, обновляется bootstrap-host)
    /usr/local/bin/<NAME>-install.sh   единственная команда с NOPASSWD

`NAME` по умолчанию `host2ns`.

## Команды

| Команда | Пароль | Что делает |
| --- | --- | --- |
| `make host2ns` | нет | применяет реестр: установка и публикация |
| `make status` | нет | зоны, имена с политикой, свежесть публикаций |
| `make check` | нет | локальный тест генерации зон |
| `make bootstrap-host HOST=x` | да | кладёт код в `/usr/local/lib` и правило sudo |
| `make authorize HOST=x` | нет | разрешает ключ хоста на NS (обычно делает `make host2ns`) |
| `make bootstrap-nsd` | да | установка и настройка NSD на этом хосте |
| `make restore` | да | перегенерировать зоны из состояния и перечитать NSD |
| `make prune` | нет | удалить имена хостов, убранных из реестра |

## Проверка

    make check     # локально, без хостов
    make status    # фактическое состояние против политики

`make status` не только показывает имена, но и сверяет их с политикой: если
политика ждёт `AAAA`, а записи нет — увидите строку `!` и итог «есть замечания».

## Ограничения

- NSD не поддерживает RFC 2136: зоны перегенерируются из состояния целиком.
- Ключ один на хост, без срока и ротации.
- Токен `nat` публикует адрес, с которого хост пришёл на NS; за бастионом это
  будет адрес бастиона — для таких хостов токен не указывают.
