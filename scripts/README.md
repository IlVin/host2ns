# scripts

| Файл | Где работает | Что делает |
| --- | --- | --- |
| `host2ns.sh` | хост | собирает адреса и имена, отправляет при изменении |
| `receiver.sh` | NS | читает stdin, проверяет, пишет состояние, применяет зоны |
| `zonegen.sh` | NS | рендер зон и конфига NSD; общий модуль |
| `rebuild.sh` | NS | зоны из состояния до старта `nsd` |
| `install-sender.sh` | хост | ключ, отправитель, таймер, проверка публикации |
| `install-ns.sh` | NS | приёмник, юнит генерации, ключи хостов, sudoers |
| `host2ns-install.sh` | хост | диспетчер `sender|ns`; единственная команда с NOPASSWD |
| `bootstrap-host.sh` | хост | кладёт код в `/usr/local/lib` и правило sudo; нужен пароль |
| `bootstrap-nsd.sh` | NS | установка и настройка NSD; идемпотентен |
| `publish.sh` | рабочая машина | читает реестр, вызывает диспетчер на хостах |
| `status.sh` | рабочая машина | зоны, имена с политикой, сверка с политикой |
| `check.sh` | рабочая машина | локальный тест генерации зон |

## Порядок работы

1. `bootstrap-nsd.sh` на NS — один раз.
2. `bootstrap-host.sh` на каждом хосте — один раз, нужен пароль.
3. `host2ns.sh` по таймеру публикует; `receiver.sh` на NS пишет и применяет.
4. `publish.sh` (через `make host2ns`) повторяет шаги 1–2 без пароля.

## Договорённости

- генерация зон только в `zonegen.sh`; второй копии быть не должно;
- «нет файла» и «нет доступа» — разные коды выхода;
- `ssh` внутри циклов вызывается с `-n`;
- в `sudo`-контексте `SSH_CONNECTION` сохраняется только для приёмника.
